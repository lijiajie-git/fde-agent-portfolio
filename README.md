## 作品一：川财 Agent 编排

**怎么看**：页面顶部有 **Agent** 和 **Skill** 两个页签。
- **Agent** 页右上角默认是"结构图"。点画布上任一节点，底部会说明它做什么、为什么这样设计。
- 下拉框里还有 7 单回放：房地产核验 236 套、发票核验、填表 · 两次确认、存续期归档、五类整理（12 份分块）、注入被拦下、放行并提醒做不到的部分。选一单后，节点会按步骤一个个点亮，底部的讲解 / 对话 / 逐份 / 校验 / 确认 / 原文页签显示每一步的细节。
- **Skill** 页是另一类活：靠人判断的工作，怎么沉淀成可复用的 Skill 和脚本。

### 1. 业务背景

券商投行部做 ABS（资产证券化）业务时，发票核对、合同字段抽取、底稿归档、房产与权证核对、Excel 填表这些活重复多、量大，而且一个数字都不能错。我在川财证券实习时，从零搭了一套只在本机运行的 Agent，把其中"规则能写成代码、一批文件进、结构化结果出"的活做成固定 workflow；写排查报告、改底稿这类靠人判断的活，做成 Skill 由人驱动。

### 2. 解决什么问题、怎么解决

用户在本机网页里说一句话、选好文件，Agent 按固定链路处理：

- **意图门**：只看用户原话和附件的数量、扩展名（不看文件名和内容），四选一：放行、追问、不归我们管、拦下。夹带指令的请求整条拦下，不调 Router，也不执行任何工具。写报告这类该走 Skill 的活，也不放给 Router。
- **Router**：只看任务原话和文件清单，挑出最少够用的能力包。输出必须是严格 JSON（选哪些包 / 缺什么输入 / 复杂度），多一个字段就拒收。
- **6 个能力包**：
  - 五类整理：把散件分到合同、产值、发票、资质、中标五类。
  - 发票核验
  - 存续期归档：60 个槽位，空槽位直接算出缺件清单。
  - 房地产核验：发票和不动产权证逐套配对。
  - 填表子步骤
  - 抽字段：公共步骤，每个值都带页码证据。
- **单执行器**：所有包共用一个执行器，模型一轮只调一个工具。
- **确定性校验**：数字全部由代码按 Decimal 精确计算，包括金额解析、大写对小写、金额 + 税额 = 价税合计、按发票号去重、合计对账、单价 = 总价 ÷ 面积。模型不碰数字。
- **交付**：写入前人工确认两次，只写 Excel 新副本，全程留痕。

例子（"房地产核验 · 236 套"那单）：Agent 读入 274 份发票和权证，逐套配对。室号 236/236 全部配上；10 张发票的小写金额在文字层里断了行，转人工核对。最后出核查汇总表，合计 ¥108,465,530.00，房源目录 236 套 × 2 件 = 472 份文件。

### 3. Agent 编排设计

- **主链是一条线**：意图门 → Router → 能力包 → 单执行器 → 四项检查 → 确定性校验 → 两次人工确认 → 只写副本 → 留痕。被拦下的请求不会走到 Router。
- **四项检查写在执行器代码里，不靠 prompt 约束**。每次调工具前都要过：
  - 工具名在本包白名单里；
  - 副作用只许读，写操作一律拒；
  - 参数符合工具的 JSON schema；
  - 路径必须是这次的输入文件之一。
- **提示词分两栏拼装**：能力包指令和业务 policy 是可信指令；用户文本、文件名、工具返回的内容一律当数据，不当指令。
- **文件多时分块处理**，每块单独开一段上下文。"五类整理 · 12 份分块"那单演示的就是这个。
- **回放页设计**：画布只放节点名、连线和当前在核的校验项，细节都收进底部面板。左下角是一叠文件卡，当前在读的那份会抽出来，读完归到"已配对 / 转人工"等几摞。回放用脱敏后的材料录制。

### 4. 优势

**评测集设计**

- **评测题从实习真活来**：主要考"填基础资产信息总表"，另有五类整理、存续期归档。参考答案直接用我实习时亲手定稿的总表和整理好的文件夹，不另编答案。
- **"缺材料"本身就是考题**：真实数据里有发票"待开具"、合同没签日期、联合体只算本家份额。正确做法是停下或标出来，不能编数；只回一句空话也不得分，必须说出缺的是什么。
- **全部用代码打分，不用 LLM 当裁判**：
  - 先过硬门槛：原件没动、两次确认后才写、写的就是确认过的格子、缺料的格子没编数。
  - 门槛过了，再按格子给部分分，另报"全对率"。
  - 关键题跑 3 次，看 3 次是不是都对（pass^3）。
- **长任务真跑三种情况**：一次填完多笔、做到一半被叫停、隔天接着上次结果续填。终态逐格对答案。
- **评测和答案隔离**：答题进程读不到答案，判分另起进程事后核对；题目、prompt、policy、schema 都用 hash 冻结。
- **边界照实写**：材料以前开发时看过，做不出文件级 held-out，所以只做任务级留出，冻结后只跑一次。目前五类整理 44 份对 43 份；写表的安全门槛每一步都守住了，原件 SHA-256 没变过。
- **单项评测**：
  - 发票核对：7 道真题从 5/7 修到 7/7。
  - 意图门：37 题对 36 题，8 条注入全部拦下，正常任务误拒 1/17，都附 Wilson 95% 置信区间。

**克制的编排选择**

- **用单执行器，不用多 agent**。底稿处理要写文件、前后步骤互相依赖、几乎没有能并行的部分，拆成多个 agent 只会多付协调成本和 token。
- **workflow 和 Skill 分开**：只把规则能写成代码的活做成 workflow，写报告、改盖章件这类靠人判断的活留给 Skill；纯确定性的活连模型都不用，留成脚本。
- **意图门不改 Router**：加意图门时，没动已冻结的 Router 契约，而是在它前面单独加一道门。
- **代码管数字和权限**：Router 看不到业务工具；算钱、核对、写文件都交给确定性代码。模型不能自己确认写入，确认 token 由后端生成、一次性消费。
- **审计层收回来了**：曾经做过 hash 链、签名锚点这样的重审计层，评估后认为复杂度超出实际需求，就删掉了，收敛成 SQLite 台账加文件锁。
- **页面也克制**：结构图上只有名字，说明全在底部面板。

## 作品二：飞书看板脱敏作品

**怎么看**：顶部是 4 个页签（总览、食品安全、业绩、履约）和门店类型筛选。点总览里的任一门店，会跳到它所在的专业页并选中这家店。

### 1. 业务背景

这是一个我做过的项目脱敏出来的版本给一个茶饮咖啡加盟品牌的区域督导做"加盟商日常管理看板"。数据是面试方提供的外部版底稿：60 家加盟店（乡镇店 49 家、商业区店 11 家），覆盖 3/13–3/16 四天，观察日为 3/16；门店、地区在底稿里就已是代号（1001 店、B 市等）。

### 2. 解决什么问题、怎么解决

督导没办法每天把 60 家店逐一看一遍。只看单一指标的话，要么所有店都报警，要么误伤正常的店。所以看板只回答一个问题：**今天先看哪几家，为什么。**

- **总览**：只汇总三个专业页的结果，不重新算综合分。
- **食品安全**：观察日的过期物料事实按记录数排序，取前 7 家；"效期疑似"（33 店）和"流程 / 设备"（37 店）两类只进入核对和补证流程，不占督导的主排名。
- **业绩**：连续两天比同类型门店基准低 5 个百分点以上的店进入候选（共 10 家），按两天平均差排序，首屏显示前 4 家。
- **履约**：按即时单"每杯均时"从高到低，取前 5 家；异常时段只作为核查背景。

数据链路：清洗 → 计算信号 → 独立验证，验证通过后才允许生成这个 HTML。生成脚本只改字段名、换算单位，不重新计算任何信号或排名。缺数据提醒和食安通知真实发到过测试群；没有真实跑过的环节，页面上统一写"尚未运行"。

### 3. 看板设计

**口径设计**

- 食安、业绩、履约分成三条泳道，不合成一个综合分，因为食安红线不能被业绩好抵消。
- 业绩和同类型门店的基准比，单位是百分点。切换门店类型时只做筛选，不在页面里重新排名。
- "每杯均时"是近似口径，不是总部 SLA。底稿里只有异常时段的记录，没有正常时段作分母，所以不算超时率。
- 缺订单明细的门店（如 1015 店）不填 0，单独标"缺订单明细"。
- 只有 4 天数据，不做周 / 月趋势；杯数字段存在口径冲突，不放进业绩主图。

**AI 分析**

- 共 23 条 AI 建议，由大模型基于已验证的看板数据和清洗明细生成。每条只有"一句发现 + 一句建议"，例如"1015 店业绩跌幅第 1，但 4 天都没有订单明细 → 先电话确认营业和数据上报"。
- 生成看板时会校验：建议里提到的门店必须真实存在，发现和建议都不能为空。
- AI 只给建议，不改动排序。建议是静态草稿，数据重跑后要重新生成。

**对用户注意力的克制**

- 前 7 / 前 4 / 前 5 是督导首屏能处理的容量，不是业务阈值，页面顶部写明了这一点；其余门店要点"展开"才看到。
- 业绩排行榜不用颜色深浅表示风险；食品安全页签也不用红色。
- 疑似类记录不进主排名；没有真实运行记录的环节，不显示发送数和回复数。
- AI 卡片去掉了"自动化建议""待督导确认"等附加标签，只留一句发现、一句建议。

### 4. 优势

- **口径诚实**：事实、规则候选、业务结论分开写。看板只说"原表存在这条记录"，不替业务认定原因、责任，也不认定问题已经处置完毕。
- **AI 有边界**：AI 建议引用的门店必须在数据里，只补充"该先做什么"，不改变排名。
- **省督导的注意力**：每页首屏只放督导当天处理得完的数量，其余进入通知或待排期，不在主屏上堆数字。
